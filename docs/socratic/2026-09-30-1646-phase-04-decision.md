## 판단

- 확인됨: Phase 04 계획은 원격 main에 반영됐고 approval UI, 요청 ID, audit record, fail-closed 동작, write 지원 보류 범위를 명시한다.
- 추론: approval을 연결하려면 Codex App Server의 양방향 stdio JSON-RPC가 필요하다. 현재 `exec --json`을 유지하면 앱 내 action approval을 지원하지 못하거나 신뢰하기 어렵다.
- 미확인: provider protocol 변경에 대한 사용자의 선호 결정.

## 다음 계획

1. Codex App Server 통합에 대한 사용자의 명시적 결정을 받는다 — 근거/의존성: 현재 `codex exec` 구조에서 provider transport가 바뀐다 — 확인 방법: 사용자의 직접 승인.
2. 승인 뒤 protocol handshake/event validation을 fixture test와 함께 구현한다 — 근거/의존성: App Server 요청은 비동기 양방향이다 — 확인 방법: 결정론적 approval flow tests.
3. 지원 OS의 sandbox 구현 검증 전까지 write mode를 비활성화한다 — 근거/의존성: approval UX만으로 OS 경계가 강제되지 않는다 — 확인 방법: 실제 platform 검증과 결과 문서화.

## 중단 또는 방향 전환 조건

- 필요한 Codex CLI가 App Server를 지원하지 않거나 action 실행 전 pause 동작을 검증할 수 없으면 현재 read-only `exec` 경로를 유지하고 write 기능을 제공하지 않는다.
